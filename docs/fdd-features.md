## 4. order-service

### 4.1 Создание заказа
**Как** официант **я хочу** создать заказы для стола **чтобы** кухня могла начать готовить.

`table_number` — опциональное поле (1–999); `customer_name` и `notes` — опциональные строки.

| Сценарий | Ожидаемый результат |
|---|---|
| Валидный заказ | 201, `status: CREATED`, список позиций заполнен, `dish_name` сохранён |
| Расчёт суммы | `total_amount` = Σ(цена × количество) |
| Пустой список позиций | 422 |
| Отсутствует поле items | 422 |
| `table_number = 0` | 422 |
| `table_number = 1000` | 422 |
| `quantity` позиции > 100 | 422 |
| `notes` позиции > 500 символов | 422 |
| Снимок цены | `price_at_order` сохраняется из menu-service на момент заказа |

**Покрыто:** `tests/features/test_order_lifecycle.py::TestFeatureCreateOrder`

### 4.3 Жизненный цикл статуса заказа
**Как** персонал кухни **я хочу** продвигать статус заказа **чтобы** команда знала прогресс.

Жизненный цикл: `CREATED → IN_PROGRESS → READY → CLOSED`  
Отмена возможна из: `CREATED`, `IN_PROGRESS`  
`CLOSED` и `CANCELLED` — терминальные состояния без исходящих переходов.

| Сценарий | Ожидаемый результат |
|---|---|
| Взять в работу | 200, `status: IN_PROGRESS`, `taken_at` установлен |
| Отметить готовым | 200, `status: READY` |
| Закрыть заказ | 200, `status: CLOSED`, `closed_at` установлен |
| Отменить из статуса CREATED | 200, `status: CANCELLED` |
| Отменить из статуса IN_PROGRESS | 200, `status: CANCELLED` |
| Невалидный переход (CREATED → CLOSED) | 422, сообщение содержит «Доступные переходы» |
| Отменить CLOSED заказ | 422, сообщение содержит «финальное состояние» |

**Покрыто:** `tests/features/test_order_lifecycle.py::TestFeatureOrderStatusLifecycle`

---

Резервирование учитывает активные заказы со статусом `CREATED` и `IN_PROGRESS`.

| Сценарий | Ожидаемый результат |
|---|---|
| Достаточно продуктов на складе | 201, заказ создан |
| Недостаточно продуктов | 422, сообщение содержит «Недостаточно продуктов на складе» |

| Блюдо без состава (рецепта) | 201, проверка не выполняется |

**Покрыто:** `tests/features/test_order_lifecycle.py::TestFeatureStockFeasibility`

### 4.6 Списание продуктов при переходе в READY
